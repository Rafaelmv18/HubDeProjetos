Quem vê o quê, à primeira vista.

O que diferencia o Hub é o acesso hierárquico, então a identidade visual nasce dele. Imagine o setor como uma roda: cada fatia é um grupo, cada anel é um cargo e, quanto mais perto do centro, mais a pessoa enxerga.

Cores

Use sempre o nome do token, nunca o valor em hexadecimal. O número em cada amostra é o contraste calculado na hora para o tema atual: texto precisa de pelo menos 4,5:1. Troque o tema no menu e veja os valores mudarem.

Por que tokens? Com var(--primary) em vez de #0b5d4e, o tema escuro funciona sozinho e uma mudança de cor é feita em um lugar só, não em 300 arquivos.

Movimento

Movimento só responde a uma ação ou mostra uma mudança feita por outra pessoa. Use motion-fast (120 ms) em passar o mouse e motion-base (200 ms) para abrir janelas e mover cards. Quem pede movimento reduzido no sistema não vê animação.

Exceção aprovada: as telas de entrada (entrar, criar conta e recuperar senha) são a vitrine da marca e seguem as regras de movimento da landing page, com animação de entrada e animação contínua decorativa (anéis, equipe em órbita, cartões de aviso de exemplo). Dentro do aplicativo a regra acima continua valendo. Toda animação dessas telas também é desligada para quem pede movimento reduzido no sistema.

Ícones

Os wireframes usam emoji como rascunho. No produto, eles são trocados por estes ícones, que seguem a cor do texto e têm o mesmo desenho em qualquer sistema. Tamanho padrão: 16 px; 20 px em barras e botões só com ícone.

Ações

Use no máximo um botão primário por área da tela: ele marca a ação mais importante ali. Use o de perigo só para ações que apagam algo, e sempre com confirmação.

Botão só com ícone precisa de aria-label, senão o leitor de tela não sabe o que ele faz. Use Tab para ver o anel de foco.

Como usar no código

Quando o projeto começar, o bloco de tokens e os componentes do <style> desta página viram os arquivos CSS do app. No React, cada classe hub- vira um componente, para ninguém repetir a marcação.

/* Certo: usa o token, funciona nos dois temas */
.painel { background: var(--surface); padding: var(--space-4); }

/* Errado: valor fixo, quebra no tema escuro */
.painel { background: #ffffff; padding: 15px; }
// Exemplo de como um componente pode ficar no React
function VisibilityBadge({ type, label }) {
  return (
    <span className={`hub-vis hub-vis--${type}`}>
      <svg className="hub-icon"><use href={`#vis-${type}`} /></svg>
      {label}
    </span>
  );
}

Os componentes do design system já existem em frontend/src/design-system/. A aparência é a mesma desta página; só que, no código, os nomes das classes ficaram em português (por exemplo, hub-botao no lugar de hub-btn).

Regras para todo código novo

  • Os tokens --brand-* e --on-gema valem igual nos dois temas, porque são as cores fixas do logotipo, que não muda no tema escuro (onde o --primary vira verde-claro).
  • Já existem em frontend/src/design-system/ os componentes Marca (logotipo, com o SimboloDaMarca, só o desenho da roda) e Orbitas (anéis e equipe em órbita, decorativo, das telas de entrada), além de Botao, Campo, Abas e Aviso. Use-os em vez de refazer. Por enquanto os ícones ficam dentro de cada peça; um componente Icone único só virá quando houver mais ícones.
  • Nenhuma cor ou espaçamento fixo fora do bloco de tokens.
  • Precisou de um valor novo? Adicione um token aqui antes de usar.
  • Componente novo entra nesta página, com os estados de carregando, vazio e erro quando fizer sentido.
  • Cor nunca é o único sinal: junto dela vem ícone ou texto.
  • Tudo precisa funcionar só com teclado e ter foco visível.
